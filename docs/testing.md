# Verification and test limitations

## Native CI and smoke tests without devices

The matrix in `.github/workflows/checks.yml` runs formatting, Clippy, Rust tests,
Needle bridge tests and builds on Linux, macOS and Windows for commits and pull
requests. Failure on one OS does not cancel the others. Conventional Commit
validation is also part of CI. The matrix runs a native-binary smoke test without
starting audio, a server, the tray, driver installation or an AI provider:

```sh
python3 scripts/test_cli_smoke.py --babel target/release/babel
```

On Windows, use `python scripts/test_cli_smoke.py`; the default path selects
`target/release/babel.exe`. The script requires Python 3.11+ and tests `--help`,
`--version` and `init` using temporary settings, paths containing spaces/Unicode,
OS-specific defaults and refusal to overwrite files. `--output-dir` selects the
JSON report folder. It does not use the user's `babel.toml` or credentials.

CI retains `test-evidence-<OS>` containing the toolchain, Rust test log and smoke
report for 14 days. Complete platform installers, including macOS/Windows
drivers, are generated by the release workflow for `v<SemVer>` tags or explicit
manual runs, rather than for each commit or pull request. Release package
artifacts are retained for 30 days. See [CI installers](ci-installers.md) for
names, signing and package verification. A workflow's existence does not prove
it has run: check the run result and each OS report.

During an earlier local installer validation, **303 Rust tests and 72 interface
tests passed**; seven environment-dependent tests were ignored. Packager tests
also passed: eight Linux, fourteen macOS and three Windows. The Linux test
creates and inspects real DEB, RPM and tar.gz packages using test executables,
without installing them. macOS/Windows contracts are tested with fixtures;
native SDK compilation and installer execution require their respective runners.
Interface regressions include systemd/XDG integration, login-entry identification
and draft preservation across language changes. Native macOS/Windows drivers,
capture and playback were not executed during that validation.

## Audio isolation, quality and processing failures

The following regressions use synthetic PCM, bounded queues, private executors
and temporary files. They do not open physical devices or call the user's providers:

```sh
cargo test --locked --lib execution::tests::
cargo test --locked --lib audio::passthrough::tests::
cargo test --locked --lib audio::resample::tests::
cargo test --locked --lib engine::isolation_tests::
cargo test --locked --lib session_writer
cargo test --locked --lib preparing_the_file_before_capture_does_not_add_silence_to_the_recording
```

The saturation test blocks every worker of a private processing executor and
requires the audio executor and its blocking pool to run before releasing them.
Another regression keeps the processing-copy queue full and checks that stereo
float frames continue reaching playback with identical bits and without
incrementing the audio-loss counter. Processing-copy losses have their own
counter. Control tests verify route revocation while processing is busy, without
depending on installed drivers.

DSP is tested separately: equal rates preserve float samples without constructing
filters; rate conversion keeps channels separate, rejects aliasing and preserves
continuity across blocks. This verifies the Babel operations exercised by the
test, not bit transparency of the target operating system's mixer or driver.

Two supervisor tests exercise independent synthetic routes while a writer fails
or remains pending. Both routes must keep transporting frames,
`Controller::status()` must report active routing with a visible processing
error, and closing routes must allow original routing to resume before waiting
for the stalled writer. The global drain deadline ends that wait and reports
potentially incomplete files; the test also verifies disposal of the pending
task. Another test writes/reopens a real WAV after preparing it before capture
and verifies that preparation time does not add initial silence. These writer
and WAV cases passed locally on Linux on September 30, 2026.

These portable tests belong to the Rust suite run by the CI matrix. Local results
do not demonstrate native macOS/Windows execution; check each target's run.
Worker affinity, helper priorities/limits and bounded queues are resource
policies, not latency or resource-usage benchmarks. External providers already
running are outside this policy. macOS does not use CPU pinning; on Windows,
lowering child-process priority does not apply a Babel thread's affinity mask
to those processes.

Switching capture on the original-audio path renegotiates the rate/channels and
reopens that direction's streams; on Linux, old endpoints require migration to
the new stereo float format. Tests without devices do not replace migration,
hotplug and format-switch testing on each OS. Opening/closing streams, global
CPU/memory pressure or a blocked OS call can still cause gaps, including when
stopping a session. These tests establish neither a zero-gap promise nor a p99
target.

### Original transport precision on a real audio server

On September 30, 2026, `tests/original_quality.rs` passed using two exclusively
owned null sinks in PipeWire/PulseAudio. It verified 4,800 consecutive stereo
frames (100 ms at 48 kHz) with bit-identical float32 samples, including details
smaller than one PCM16 step. Capture read only the synthetic destination monitor.
The test confirmed removal of its devices and preservation of system defaults
and existing Babel devices.

```sh
cargo test --locked --test original_quality -- --ignored --nocapture
```

This is a fidelity regression for the original-audio path at equal rates, not
a latency measurement or a guarantee of physical-converter fidelity or
resampling between different formats. For the full suite on machines with many
CPUs, `cargo test --locked --all-targets -- --test-threads=4` avoids hundreds of
mock servers and deadline tests competing simultaneously for the application's
bounded executors.

## Switching from virtual to physical output

Verified on September 29, 2026: **219 Rust tests and 50 DOM tests passed**. The
six environment-dependent tests at that time remained ignored. The private
scenario below passed with the real executable, including pause/resume within
the same recording session.

The following test uses **private** PipeWire, pipewire-pulse, WirePlumber with
the `policy` profile and D-Bus instances in a temporary directory. It does not
open ALSA/Bluetooth devices, read real microphones or change the desktop audio
session's defaults. It requires those four executables and `pactl`/`pacat`/`parec`
in PATH or `.tools/pulse/usr/bin`; `--pulse-tools` selects another directory.

```sh
CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 cargo build --bin babel --locked
python3 scripts/test_audio_routing.py --babel target/debug/babel
```

The scenario checks protection against moving Babel's own streams, absence of
capture/playback when no application uses the virtual devices and Babel is not
the system's default microphone, independent microphone/output activation,
switching the application to a simulated physical device and returning to Babel.
It repeats the sequence during a recording session: the ID and single WAV are
preserved while the audio subprocesses are new. Without `--babel`, the script
checks only PulseAudio client pinning.

Rust regressions in `engine::activity` check discarding delayed responses,
physical-device changes while paused, rapid transitions, monitor errors,
ordered shutdown before reopening, and writer continuity. DOM regressions
check the waiting state, zeroed meters, independent directions and preservation
of the session in English and Portuguese.

## Automated suite

```sh
cargo test --all-targets
```

The automated tests passed without failures during the earlier validation
reported here. Six environment-dependent checks were ignored by default then:
low-level audio, `live_engine`, two `recorded_session` scenarios, the XDG/GIO
launcher and Linux tray waiting. The normal suite works without AI credentials,
loaded local models or installed virtual devices. Check current test output for
the current totals and ignored cases.

Among other behaviors, it verifies:

- Interface language: persistent preference, system default, regional variants
  and English fallback; dashboard/tray catalogs and switching during a session
  without cancelling the worker, changing devices or overwriting drafts.
- Queue limits, interruption even with a full queue, and failure propagation.
- Resampling with aliasing rejection and continuity across blocks.
- Real WebSockets against local test servers: setup acknowledgement before
  sending audio, PCM streaming, transcripts, reconnection and cancellation.
- Local HTTP against whisper.cpp, Ollama/OpenAI-compatible chat and Piper mocks;
  multipart WAV, VAD segmentation, text alignment and response limits.
- Local management: model/component integrity, announced ports, cancellation,
  active features independent of optional preparation, and snapshots that do
  not persist temporary ports.
- External voices with the local provider without calling Piper or generating
  a discarded WAV.
- Voice synthesis and management against HTTP mocks; authentication, upload
  limits, malformed responses and errors without exposing keys or private content.
- Original transcript persistence, legitimate metadata and file permissions.
- A single WAV with simultaneous mixing, headroom, gaps, a monotonic clock,
  headers/checkpoints, draining and refusal to overwrite files.
- Device switching with stable channels, cancellation and error recovery.
- Original forwarding with preserved PCM, bounded queues, stale-audio disposal
  and cancellation even when output is saturated.
- Dashboard authorization, rejection of incorrect origins and temporary
  credentials without persistence in settings.

Mocks validate the implemented protocol; they do not measure translation
quality, remote-service latency or model availability for your account.

## Smoke tests with real local models

`scripts/test_bundled_inference.py` loads the packaged engines and pinned
Whisper Base Q5_1, Qwen3 0.6B and Piper en_US-lessac weights. It checks dynamic ports,
Whisper inference over one second of synthetic silence, translation of a fixed
sentence and two utterances in the same Piper process, including Unicode paths
and valid float WAV samples. Child processes are stopped at the end, including
on failure. It does not capture a microphone, open audio devices or use keys.

```sh
python3 scripts/test_bundled_inference.py \
  --runtime-dir artifacts/local-runtime/linux-x86_64 \
  --model-cache "$HOME/.local/share/babel/models"
python3 -m unittest discover -s scripts -p test_bundled_inference_contracts.py -v
```

The real smoke test and its four contract tests passed locally on Linux on
September 29, 2026. The runtime CI runs the same scenario on Linux x64, macOS
Intel/ARM64 and Windows x64/ARM64; check the result of each hosted run. This does
not mean the macOS/Windows scenarios have already passed locally. The initial
download uses a hash-addressed cache and requires networking; existing verified
files are reused. Python is required by this test, not by the installed
application. The test proves loading/protocol behavior, not per-language
quality, diarization, sustained memory usage or end-to-end latency.

## Linux audio-server integration

`pactl`, `parec` and `pacat` must be in `PATH`, with a running
PulseAudio/`pipewire-pulse` session. Run these tests **before** creating devices
for normal use, in a session without Babel endpoints. They create and remove
their own modules and refuse to run when endpoints with the reserved names
already exist. Do not run them during translation.

```sh
cargo test --lib audio::linux::tests::live_virtual_routes_idempotence_interruption_and_cleanup -- --ignored --nocapture
cargo test --test live_engine synthetic_original_audio_crosses_controller_and_virtual_devices -- --ignored --nocapture
```

On the development machine, Pulse tools were extracted locally; the command
used was:

```sh
PATH="$PWD/.tools/pulse/usr/bin:$PATH" cargo test --test live_engine -- --ignored --nocapture
```

The low-level test passed and confirmed idempotent creation, Babel-owned module
identity, both virtual bridges, interruption of old audio with a full queue and
module removal. It also checked that the session's default devices were unchanged.

The full test uses original forwarding with translation and transcription off,
without selecting an AI provider. It starts a named session recording only the
output. The exercised path is:

```text
synthetic tone → babel_speaker → Controller capture
               → original forwarding → babel_mic_bus → babel_microphone
               → verification capture
```

The test requires a positive capture count, audio received at the other end,
recording of the original tone, error-free stopping and endpoint removal.
Translation counters remain at zero and no AI connection opens. Even if a check
fails, the test stops the Controller, cancels and awaits helper processes, and
attempts to remove the modules before returning the error.

In earlier runs of this scenario, `ps -C parec -C pacat -o pid=,args=` showed no
processes, and `pactl list short sinks` / `pactl list short sources` showed no
`babel_*` endpoints. That absence refers to test shutdown; a subsequent
installation for normal use naturally keeps the devices present.

The current `live_engine` variant and first `recorded_session` test replace
the removed diagnostic adapter with original forwarding. Compilation and tests
without devices are not a new run of those variants against an audio server;
the historical results below must not be interpreted as a run after that change.

## Complete recording while preserving normal-use devices


This test creates four null sinks with its own random names and uses two
Controller original-audio streams, with translation/transcription off and only
recording enabled. Its signals are synthetic 440 Hz and 880 Hz tones. Removal
checks the IDs and ownership of the four temporary modules; the test does not
install/uninstall user-facing Babel endpoints and can coexist with them.

An earlier real execution produced **one 3.53 s WAV**, with both frequencies in
the same one-second window and the session name applied to the filename pattern.
Duration was compared with the session clock to detect incorrect concatenation.
The Controller stopped without error, no test `parec`/`pacat` remained, and
existing Babel endpoints were unchanged before and after the test.

The test uses only temporary settings and does not capture physical devices.
It validates recording and local integration; it does not measure AI translation
quality.

## Independent forwarding, recording and transcription

```sh
PATH="$PWD/.tools/pulse/usr/bin:$PATH" cargo test --test recorded_session idle_routing_recording_and_transcription_are_independent_without_cloud -- --ignored --nocapture
```

This second scenario also uses four exclusively owned temporary sinks and
preserves existing Babel endpoints. Both translation options remain disabled,
and no AI key is required. The recorded real execution passed in **4.81 s**, checking:

1. Both original tones are forwarded with no session, without creating the
   recordings directory.
2. Starting a recording-only session: audio keeps flowing and one WAV mixes
   both tones in the same interval, with translation counters at zero.
3. Stopping the session returns to original forwarding and finalizes a
   **2.21 s WAV** without error.
4. Starting a transcription-only session against a local HTTP server simulating
   whisper.cpp: **two recognition calls**, one TXT containing both sources and

The checks measure 440 Hz and 880 Hz in fresh captures at each phase; the test

## Windows and macOS

```sh
rustup target add x86_64-pc-windows-gnu
cargo check --all-targets --target x86_64-pc-windows-gnu
```

The Windows cross-check passed, including CPAL, providers and the native tray
event loop. It checks types and compilation; it does not run the program or
confirm driver installation, capture, playback, permissions or tray behavior on
Windows. No physical testing on Windows/macOS or macOS build was performed on
this Linux host.

Review of the CPAL workers checked bounded queues, callbacks without
allocation/networking/locks, atomic failure signals, frequent cancellation
checks and a timeout when a device stops consuming samples. The shutdown guard
uses a child token: aborting the asynchronous task requests worker cancellation
without cancelling the supervisor and hiding a device error. A stalled OS call
cannot be interrupted by that token. An identity/direction registry prevents
reopening the same endpoint until the previous worker actually releases the
resource; cancelling a task does not prove the driver closed the stream.
Drivers and native dependencies remain outside the project's
`forbid(unsafe_code)` guarantee.

Monitor tests use models/fixtures to verify identity, direction, exclusion of
the Babel process and failures that close the route. Supervisor tests verify
waiting, cancellation, stale-audio disposal, physical-device switching and
session continuity. They do not fully simulate macOS privacy policies,
every Windows application's session enumeration or real-driver behavior.

### Validation checklist for the target operating system

Use macOS 14.2+ or Windows 10/11 with both native Babel cables installed as
described in [native drivers](native-drivers.md). BlackHole/VB-CABLE cables are
optional alternatives with their own installation. Record the OS version,
architecture, commit, driver, physical device, calling application and granted
permissions. Start with translation/transcription off, using synthetic audio
and a test application that can select input/output independently. Use
headphones if you later test a physical microphone.

| Scenario | Expected result to verify |
|---|---|
| No application using the cables; physical default microphone | Both routes wait; Babel opens no physical stream, and instantaneous meters are zero. |
| Babel is the default microphone, with no capturing application | The microphone opens, meters respond and enabled commands can listen; output remains inactive. |
| Default changes from Babel to a physical microphone, with no explicit consumer | The microphone closes and commands stop listening. |
| Babel selected only as default output, without playback | Output remains inactive; Babel's own streams do not cause feedback. |
| Application captures only the virtual microphone endpoint | Only the microphone opens; audio reaches application capture and Babel output keeps waiting. |
| Application plays audio only to the output cable | Only output opens; audio reaches the chosen physical destination. |
| Both endpoints in use | Two independent routes, without feedback or duplicated audio. |
| Application switches output to a physical device while keeping the virtual microphone | The output route closes; the microphone remains active. Returning to the cable resumes output without replaying accumulated audio. |
| Application switches microphone to a physical device while keeping virtual output; system default is also physical | The microphone route closes; output remains active. Babel voice commands cannot be triggered by output audio. |
| Default microphone changes to a physical device, but an application still captures Babel | The explicitly connected application continues receiving audio; the microphone and enabled commands remain active. |
| Physical device changed through dashboard/tray during an active session | The new physical device receives the route; session and files remain the same, without backlog replay. |
| Physical device disconnected/reconnected, or a second physical device selected | Diagnostics and recovery attempts for the selected identity; no silent fallback to the default. |
| Original recording session, translation/transcription off | One WAV contains both sources on the same timeline; pause/resume preserves the ID and file. |
| Missing permission/API, ambiguous Windows pair or unrecognized driver | The affected direction remains closed and reports the problem. A global enumeration error may close both. |
| Exit and restart | Streams and workers from the previous process terminate; persisted selections resolve to the same endpoints. |

Check activity in both the dashboard and the operating system's audio tool;
a zero meter alone does not prove capture was closed. On macOS, select each
Babel device directly, without Aggregate/Multi-Output. On Windows, start with
shared WASAPI and record whether a new session remains waiting; do not treat
ASIO, Kernel Streaming or exclusive mode as validated.

Save evidence for each scenario: time, state of each route, session ID,
selected endpoint and synthetic WAV duration/samples where applicable. Do not
include tokens, API keys or personal voice in test artifacts. Mark each row as
passed, failed or not run, and attach diagnostics for failures. This table is
a pending checklist for target hardware, not a record of completed execution.

## Native drivers: tests separate from the application

The `native/macos`, `native/windows/transport` and `native/windows/installer`
workspaces neither inherit nor remove the application's `forbid(unsafe_code)`.
The safe transport has its own tests; FFI, SDK and WDK require separate
validation. Run these commands from the checkout:

```sh
cargo test --locked --manifest-path native/macos/Cargo.toml
cargo test --locked --manifest-path native/windows/transport/Cargo.toml --lib
cargo test --locked --manifest-path native/windows/installer/Cargo.toml
python3 -m unittest discover -s native/windows/tests -p 'test_*.py' -v
cargo test --locked --example native_driver_smoke
```

On Linux, the first command tests the core and Rust contract; it does not compile
the bridge against the Apple SDK. Windows transport tests cover PCM frames,
memory limits, isolation and flushing when an endpoint stops. Its C++/Rust
harness uses WDK stubs only in tests and does not validate real IRQL/DPC behavior.
The installer has portable tests rejecting similar identities and OEM paths
that escape the package.

Cross-compilation checks also cover the installer:

```sh
cargo clippy --locked --all-targets --target x86_64-pc-windows-gnu -- -D warnings
cargo clippy --locked --all-targets --target x86_64-pc-windows-gnu \
  --manifest-path native/windows/installer/Cargo.toml -- -D warnings
```

`.github/workflows/native-checks.yml` runs portable core, ABI shim and package
contract checks for commits and pull requests. The reusable
`.github/workflows/native-drivers.yml` separates portable tests, macOS SDK builds,
x64/ARM64 WDK builds and packaging for all three systems; release packaging is
requested only by the release workflow for version tags or manual runs. These
workflows use hosted runners and pinned versions/hashes of official SDK/WDK
NuGet packages. CI does not load drivers or open audio devices. The Windows x64
application installer is exercised in a temporary directory; the runtime matrix
performs inference separately with synthetic inputs on five targets.
Development artifacts are labeled accordingly. A workflow in the repository
is not evidence that it has executed.

After compiling, signing and installing on the target operating system, run the
synthetic smoke test described in
[native drivers](native-drivers.md#verifying-the-installed-transport). It requires
four device IDs and never selects system defaults. Also test multiple
readers/applications, OS suspend/resume, physical-device switching during a
session, disconnection, reinstallation, removal and restart. On Windows, run
Driver Verifier/WDK validation on a test machine and check notifications, DPC
cancellation and audio recovery before production. On macOS, validate the bundle
in real CoreAudio, microphone privacy, clock behavior and buffer sizes. None of
these results can be inferred from queue tests on Linux.
