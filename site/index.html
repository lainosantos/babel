Audio that keeps moving

Selectable virtual devices connect to your real microphone and headphones. Switch physical devices during a session, with a brief transition if needed.

Original input and output use a dedicated routing path, preserving their configured native sample rate and channels. Processing uses bounded copies so slow AI or file operations do not block routing.

Live translation

Choose languages and a translation provider for each direction. Configure models and supported prompts. Use streaming speech translation or a local recognition, translation, and speech pipeline.

Both directions use the model's native default voice. Embedded local translation selects its speech model for the target language automatically. Latency and voice preservation depend on the model.

The words, as spoken

Transcribe original speech with dedicated speech-to-text providers. Choose a provider and language for each source, independently of translation.

One text file combines the selected sources. Optional timestamps and provider-supplied speaker labels keep the conversation readable. Deepgram supports speaker diarization; other adapters have different limits.

Remember the beginning

Record the selected originals into one mixed WAV. A rolling memory buffer keeps the previous ten minutes by default, with configurable retention.

Opt in at session start to include a chosen portion of recent history in recording, transcription, or both. See the available time live. Set an absolute base folder, session name, and filename pattern.

Retry incomplete file sessions from retained originals while Babel stays open. Spill into the system temporary folder is encrypted, with its key held only in memory.

Say it. Connect your tools.

Speak your configurable wake name, then a command. Local speech recognition and Needle 3 select a tool from your connected MCP integrations.

Only your original microphone activates commands. Connect HTTP or stdio servers, configure supported authentication, and adjust decision confidence from zero to one. Desktop feedback follows activation, processing, success, and failure.
